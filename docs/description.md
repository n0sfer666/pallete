# Pallete — подробное описание

Pallete — настольное приложение для сбора и ведения цветовых палитр. Главная идея: вставить любой текст, где есть цвета (кусок CSS, таблицу из дизайн-дока, список hex из чата), и получить готовые палитры — без ручного переписывания.

Приложение полностью офлайн: не ходит в сеть, не собирает телеметрию. Данные хранятся в обычных JSON-файлах на диске.

## Проекты и workspace

- **Проект** — это один файл `*.palette.json` со списком палитр. Внутри проекта можно держать сколько угодно палитр.
- **Workspace** — список проектов, которые приложение «помнит». Хранится отдельно (в пользовательской директории приложения).
- **Новый проект**: указать папку и имя → создаётся файл `<имя>.palette.json` в этой папке и сразу открывается.
- **Открыть…**: выбрать существующий `*.palette.json` — он добавляется в workspace и открывается.
- **Убрать из workspace**: удаляет проект из списка, **сам файл на диске не трогается**.
- Если файл проекта переместили или удалили, в списке он помечается как недоступный.
- **Автосохранение**: любые изменения проекта сохраняются на диск автоматически (с небольшой задержкой после последнего действия) — отдельной кнопки «Сохранить» нет.

## Палитры и цвета

Интерфейс — три колонки: **Проекты → Палитры → Настройка палитры**.

Палитра:
- добавить, переименовать, **дублировать** (копия со всеми цветами и новыми id), удалить.

Цвет внутри палитры:
- добавить (создаётся серый `#CCCCCC`, дальше правится);
- редактировать значение: hex (`#RRGGBB` или `#RRGGBBAA`), RGB (`rgb(r,g,b)` / `rgba(r,g,b,a)`), нативная системная пипетка, отдельный слайдер и поле для **alpha**;
- задать **имя** цвета (необязательно);
- скопировать (формат — из настроек, см. ниже);
- удалить.

## Генератор палитр

У пустой палитры в шапке колонки «Настройка палитры» есть свитч **«Генерация»**: палитра собирается целиком из одного базового цвета в OKLCH — оттенки, тональная шкала 50…950, градиент A → B, шкала прозрачности, цветовые гармонии, семантический набор ролей. Перестроение живое, отменяется одним undo.

📖 Подробно: [docs/palette-generator.md](./palette-generator.md).

## Импорт палитр

### Способы открыть импорт

- Кнопка/диалог импорта внутри приложения — вставить текст в поле слева, справа сразу показывается превью распознанных палитр.
- **`Ctrl/Cmd + V`** в любом месте окна (кроме текстовых полей) — открывает диалог импорта с текстом из буфера обмена.
- **Перетащить файл** в окно приложения — поддерживаются `.txt`, `.md`, `.css`, `.scss`. Содержимое файла подставляется в поле импорта.

В диалоге есть переключатели:
- «Первая строка — заголовок» (для таблиц),
- «Первая колонка — имена палитр» (для таблиц),
- «Hex без `#`» (см. ниже).

Обычно они определяются автоматически; переключатели нужны, когда автоопределение ошиблось.

### Что распознаётся как цвет

| Формат | Пример | Примечание |
|---|---|---|
| Hex с `#` | `#fff`, `#66BB6A` | 3 или 6 знаков |
| Hex с альфой | `#abcd`, `#11223380` | 4 или 8 знаков; альфа — последние 1–2 знака |
| `rgb()` | `rgb(102, 187, 106)` | каждый канал 0–255 |
| `rgba()` | `rgba(0, 0, 0, 0.5)` | альфа 0–1, выходит за диапазон — обрезается |
| Hex без `#` | `66BB6A`, `11223380` | **только если включён переключатель «Hex без `#`»**; распознаются только 6 или 8 знаков |

- Короткие формы hex разворачиваются: `#abc` → `#AABBCC`, `#abcd` → `#AABBCC` + альфа.
- `rgb(...)` с каналом > 255 (`rgb(300,0,0)`) игнорируется целиком.
- Цвета можно мешать в одной строке — порядок сохраняется: `#111 rgb(0,0,0) #222` → три цвета.

### Что НЕ распознаётся

Эти форматы парсер **не понимает** — цвета из них в палитру не попадут:

- `hsl()` / `hsla()` (HSL есть только как формат **копирования**, не импорта);
- именованные цвета CSS: `red`, `white`, `cornflowerblue` и т. п. (в CSS/SCSS-переменных значение `$white: white;` не даст цвета — нужно `$white: #fff;`);
- современные функциональные нотации: `rgb(255 0 0)` (через пробел, без запятых), `rgb(100% 0% 0%)` (проценты), `lab()`, `lch()`, `oklab()`, `oklch()`, `color(...)`, `hwb()`;
- 3-значный hex **без** `#` (`abc`) — без решётки распознаются только 6- и 8-значные;
- цвета внутри `url(...)`, изображений, base64 и прочего бинарного мусора.

Если в тексте вообще не нашлось ни одного распознаваемого цвета — превью покажет «Палитры не распознаны», импортировать будет нечего.

### Форматы текста и группировка

Парсер пробует распознать структуру текста в таком порядке:

**1. CSS / SCSS-переменные.** Если в тексте есть объявления вида `--name: …;` или `$name: …;`, где в значении есть цвет — срабатывает этот режим. Переменные группируются в палитры:

- **по комментариям-секциям.** Строка-комментарий целиком (`// Gray Scale`, либо однострочный `/* Status */`) задаёт имя палитры; все переменные до следующего такого комментария попадают в неё. Внутри секции переменные не дробятся. Из нескольких подряд идущих комментариев берётся последняя непустая строка. Пустая секция (заголовок без переменных под ним) палитру не создаёт.
- **по общему префиксу имени.** Переменные до первого комментария-секции (а если секций нет вообще — весь текст) группируются по префиксу = часть имени до последнего дефиса: `deep-blue-800` → префикс `deep-blue`. Если с одним префиксом ≥ 2 переменных — это палитра с именем-префиксом. Всё остальное (одиночки, имена без дефиса вроде `$white`) уходит в палитру **«Variables»**.
- Трейлинг-комментарии игнорируются: `$ocean-400: #40e0d0; // Main turquoise` → имя цвета `ocean-400`, комментарий отбрасывается.

Пример:

```scss
// Gray Scale
$gray-50:  #fafafa;
$gray-900: #171717;

// Primary Colors (Ocean Theme)
$ocean-400: #40e0d0; // Main turquoise
$ocean-500: #14b8a6;

$white: #fff;
$black: #1a1a1a;
```

→ палитры: **Gray Scale**, **Primary Colors (Ocean Theme)**, **Variables** (в неё попадут `white` и `black` — у них нет общего префикса с дефисом).

**2. Таблицы.** Если структуры переменных нет, текст разбирается как таблица:

- разделители ячеек — вертикальная черта `|` (Markdown / ASCII-таблицы) либо, если черты нет, запятые / точки с запятой / пробелы;
- первая строка считается заголовком, если в ней нет ни одного цвета (можно переопределить переключателем);
- первая колонка считается именами палитр, если в большинстве строк её первая ячейка — не цвет (можно переопределить);
- **каждая строка таблицы → отдельная палитра** (имя — из первой ячейки, либо `Palette 1`, `Palette 2`, …).

**3. Просто список цветов.** Если ни переменных, ни таблицы — все найденные в тексте цвета складываются в одну палитру **«Imported»** (порядок появления сохраняется). Так обрабатывается, например, список hex, скопированный из чата.

### Имена цветов

- CSS / SCSS: имя цвета = имя переменной (`gray-50`, `white`). Если в одном значении несколько цветов — первый получает имя переменной, остальные `name-1`, `name-2`, …
- Таблицы: имя берётся из текста рядом с цветом в ячейке (после цвета; если после ничего нет — то, что до).
- Список цветов («Imported»): имён нет.

### Куда попадает импорт (нет активного проекта)

Импортировать можно, даже если проект не открыт — кнопка импорта не блокируется:

- **нет ни одного проекта** в workspace → сразу открывается диалог «Новый проект»; после создания палитры импортируются в него (повторно вводить текст не нужно);
- **ровно один проект** → спрашивается подтверждение «Сохранить в проект X?». «Да» — импорт в него; «Нет, новый проект» — диалог создания нового и импорт туда;
- **несколько проектов** → открывается список проектов; можно выбрать любой либо нажать «+ Новый проект».

### Конфликты имён палитр

Если имя импортируемой палитры совпадает (без учёта регистра) с уже существующей в проекте, диалог покажет число конфликтов и предложит стратегию:

- **merge** — дописать цвета импортируемой палитры в существующую (по умолчанию);
- **replace** — заменить существующую палитру целиком;
- **skip** — пропустить, оставить как есть.

Импорт — одна операция в истории, его можно откатить целиком (Undo).

### Ограничения

- Размер вставляемого текста — до **1 МБ**.
- Суммарное количество цветов в импорте — до **10 000**.

При превышении импорт не выполняется, диалог показывает предупреждение.

## Копирование цвета

Кнопка копирования у цвета кладёт значение в буфер обмена в формате из настроек:

- **hex** — `#RRGGBB` (или `#RRGGBBAA`, если альфа ≠ 1);
- **rgb / rgba** — `rgb(r, g, b)` / `rgba(r, g, b, a)`;
- **hsl / hsla** — `hsl(h, s%, l%)` / `hsla(h, s%, l%, a)`.

## Undo / Redo

История изменений ведётся по командам. Откатываются и повторяются:

- добавление, переименование, дублирование, удаление палитры;
- добавление, изменение (hex / rgb / alpha / имя), удаление цвета;
- переименование проекта;
- импорт палитр (целиком).

Открытие другого проекта и создание нового **очищают историю** — откатить «через» смену проекта нельзя.

## Темы и настройки

В настройках:

- **Тема** — светлая / тёмная / системная;
- **Формат копирования** — hex / rgb / hsl;
- **Принимать hex без `#` при импорте** — тот же переключатель, что в диалоге импорта.

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl/Cmd + V` | импорт палитры из буфера обмена (вне текстовых полей) |
| `Ctrl/Cmd + Z` | undo |
| `Ctrl/Cmd + Shift + Z` | redo |
| `Delete` / `Backspace` | удалить выбранную палитру или цвет |
| `Esc` | отмена инлайн-переименования палитры |

## Хранение данных

- Проекты — файлы `*.palette.json` там, где их создали/открыли. Это обычный JSON, его можно держать в git, передавать, бэкапить.
- Workspace (список проектов, выбранная тема и т. п.) — в пользовательской директории приложения (`identifier` приложения — `dev.n0sfer.pallete`). Переустановка приложения эти данные не затирает.
