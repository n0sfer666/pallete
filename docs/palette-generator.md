# Генератор палитр

Генератор строит палитру целиком из одного базового цвета — вместо того чтобы подбирать оттенки вручную. Вся математика идёт в **OKLCH**: это перцептивное пространство, где одинаковый шаг светлоты выглядит одинаковым шагом и для жёлтого, и для синего. Любой цвет, вышедший за пределы sRGB, «прижимается» по хроме к границе гамута — светлота и hue при этом сохраняются.

## Как включить

Свитч **«Генерация»** в шапке колонки **«Настройка палитры»**. Он показывается, только когда палитра **пустая** (или генератор уже включён) — чтобы случайно не затереть набранные вручную цвета.

Включили → под шапкой появляется дропдаун режима и поля параметров, палитра сразу заполняется цветами.
Выключили → сгенерированные цвета **остаются в палитре** как обычные, их можно править и удалять.

Пока генератор включён, список цветов доступен только для чтения: правка отдельного цвета не имеет смысла, потому что следующее движение любого параметра перестроит палитру заново.

## Общее поведение

- **Живое перестроение**: любое изменение параметра сразу пересобирает палитру.
- **Undo одной операцией**: перестроение — один шаг истории. Ctrl/Cmd+Z возвращает предыдущий набор цветов целиком, а не по одному цвету.
- **Состояние генератора не сохраняется** в файл проекта: в `*.palette.json` попадают только сами цвета. Закрыли проект — свитч снова выключен.
- Максимум **64 цвета** за одну генерацию.

## Режимы

### Оттенки (shade)

Шкала светлоты вокруг базового цвета: `от x` `до y` с шагом `z`, база стоит на ступени `база`.

- Ступени — как в Tailwind: 50, 100, …, 900. Имя цвета = номер ступени.
- Ступень, равная базовой, получает **точный** базовый hex; остальные сдвигаются по светлоте (вверх — к белому, вниз — к чёрному), hue и хрома сохраняются.
- Если база почти белая или почти чёрная, соседние ступени схлопываются в один и тот же hex — генератор отказывается строить такую шкалу и показывает ошибку.

### Тональная шкала (tonal)

11 фиксированных ступеней **50, 100, …, 900, 950** с зашитыми целевыми значениями светлоты (0.97 → 0.20) — как в дизайн-системах вроде Tailwind/Material. Единственный параметр — базовый цвет.

- **Анкор** — ступень, чья целевая светлота ближе всего к базе. Она получает точный базовый hex; при равном расстоянии выигрывает более светлая ступень.
- Хрома идёт «колоколом»: максимум в середине шкалы, спад к светлым и тёмным краям, нормировка — по анкору.

### Градиент A → B (interpolate)

Плавный переход между двумя цветами за N шагов (N ≥ 2). Имена — `1`, `2`, …, N. Концы попадают в результат точно.

- **OKLab** (по умолчанию) — прямая интерполяция; переход между «противоположными» цветами идёт через приглушённую середину.
- **OKLCH** — интерполяция по hue кратчайшей дугой: середина остаётся насыщенной.
- Если один конец ахроматичный — белый, чёрный или почти серый (хрома < 0.02, сюда попадают и UI-серые вроде slate-300) — внятного hue у него нет, и для построения дуги он берёт hue второго конца. Иначе градиент «серый → синий» уехал бы через розовую середину. Сам конец при этом остаётся **точно** тем цветом, который выбрали: hue заимствуется только для промежуточных шагов.
- Каждый конец задаётся пипеткой или hex-полем; в формате `#RRGGBBAA` можно указать прозрачность — она интерполируется линейно от A к B. Пипетка меняет только цвет: выставленная прозрачность конца при этом сохраняется.

### Шкала прозрачности (alpha)

Один и тот же hex с разной альфой: `от %` `до %` с шагом `%`. Имя цвета = процент (`10`, `20`, …), `alpha = N / 100`. Ряд строится тем же алгоритмом, что и в режиме «Оттенки».

### Гармония (harmony)

Набор цветов, повёрнутых по hue относительно базы.

| Схема | Углы | Имена |
|-------|------|-------|
| Комплементарная | 0, +180 | `base`, `complement` |
| Аналоговая | −угол, 0, +угол | `analogous-1`, `base`, `analogous-2` |
| Триада | 0, +120, +240 | `base`, `triadic-1`, `triadic-2` |
| Раздельно-комплементарная | 0, +180−угол, +180+угол | `base`, `split-1`, `split-2` |
| Тетрада (квадрат) | 0, +90, +180, +270 | `base`, `tetradic-1` … `tetradic-3` |

Угол настраивается только для аналоговой и раздельно-комплементарной схем (по умолчанию 30°, допустимо 0 < угол < 180).

`base` — **точно выбранный** hex. Производные цвета получают светлоту базы и **одну общую хрому**: минимум из хромы базы и максимально допустимых в sRGB хром для их hue. Это «сводит цвета в одну семью» — иначе, например, жёлтый производный выглядел бы кричаще ярче синего. Побочный эффект осознанный: база может оказаться насыщеннее производных, а приглушённая база даёт приглушённую гармонию.

### Семантический набор (semantic)

Роли интерфейса из одного базового цвета: `primary`, `success`, `warning`, `danger`, `info`, `neutral`.

- `primary` — точный базовый hex.
- `success` / `warning` / `danger` / `info` — **фиксированные hue** (145° / 75° / 25° / 250°), светлота и хрома наследуются от базы. Hue базы на роли не влияет: danger остаётся красным, даже если база зелёная. А вот хрома наследуется — у ахроматичной базы роли выйдут серыми, см. [Ограничения](#ограничения-и-краевые-случаи).
- `neutral` — серый с лёгким оттенком бренда: hue базы, хрома ≈ 0.02.
- **Чекбокс «со шкалой»**: каждая роль разворачивается в три ступени тональной шкалы — `role-light` (tonal 100), `role` (tonal 500), `role-dark` (tonal 800). Итого 18 цветов.

## Ошибки

Некорректные параметры не ломают палитру: под полями появляется текст ошибки, а палитра на это время очищается. Как только параметр снова валиден — цвета возвращаются. Отменять ошибочный шаг вручную не нужно.

Типовые сообщения: нулевой или отрицательный шаг, диапазон вне 0…1000 (или 0…100 % для альфы), больше 64 цветов, база вне диапазона ступеней, вырожденная шкала оттенков, непарсящийся hex.

## Ограничения и краевые случаи

- **Белая и чёрная база.** В тональной шкале анкор берёт точный hex базы, поэтому у `#000000` разрыв между 900 и 950 заметно больше остальных. В семантическом наборе при L = 1 или L = 0 хрома обнуляется гамутом, и все роли схлопываются в один цвет — базу для семантики стоит брать средней светлоты.
- **Колокол хромы в тональной шкале работает не для всех баз.** Если база очень светлая и насыщенная (жёлтый, лайм, циан), её анкор — светлая ступень, и «поднять» хрому средних ступеней выше границы sRGB невозможно: гамут срезает их, и хрома просто монотонно падает от 50 к 950 вместо колокола. Это ограничение sRGB, а не ошибка расчёта.
- **Серая база.** Хрома базы задаёт потолок семьи, поэтому чистый серый (хрома ≈ 0) в гармонии даст серые же цвета, а в семантическом наборе — серые роли (кроме `neutral`, у которого хрома задана явно). Оттенок из серой базы взять неоткуда: hue у неё не определён.
- **8-битный hex.** Итоговые цвета округляются до `#RRGGBB`, поэтому hue может «уехать» на доли градуса, а очень близкие ступени — совпасть.
