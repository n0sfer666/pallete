# Спецификация: Генератор палитр

Дата: 2026-07-11
Статус: согласована, к реализации

## Контекст

Сейчас палитра наполняется вручную (`+ Цвет`) или импортом (CSS/SCSS/таблицы).
Типовой сценарий дизайн-системы — «есть один брендовый цвет, нужна шкала оттенков» —
требует ручного подбора каждого шейда.

Фича добавляет в шапку колонки «Настройка палитры» переключатель «Генерация»:
для **пустой** палитры он раскрывает панель параметров, и палитра целиком строится
из одного (или двух) опорных цветов по выбранному алгоритму, с живым пересчётом.

Вся цветовая математика — в **OKLCH/OKLab** (перцептивно равномерное пространство):
шаги шкалы выглядят одинаковыми на глаз, hue не «плывёт», градиенты не грязнят середину.

## Требования

### Функциональные

#### Общие правила (все режимы)

- **Видимость.** Свитч «Генерация» показывается в шапке `PaletteDetails` только если
  у палитры нет цветов, ИЛИ если генератор для этой палитры уже включён.
- **Дропдаун режимов** (6 пунктов): `shade`, `tonal scale`, `interpolate`, `alpha ramp`,
  `harmony`, `semantic set`.
- **Live-пересчёт.** Изменение любого параметра целиком перестраивает список цветов палитры.
- **Undo.** Каждая перестройка — одна операция undo (`generate palette`), Ctrl+Z откатывает
  весь набор цветов разом.
- **Заморозка.** Выключение свитча оставляет цвета в палитре как обычные редактируемые —
  генератор их больше не контролирует.
- **Состояние генератора не персистится.** Живёт только в UI-сторе сессии; формат файла
  проекта (`version`) и Rust-модель не меняются. После перезапуска цвета на месте,
  генератор чист.
- **Базовый цвет общий между режимами.** Переключение режима сохраняет пикер; числовые
  параметры у каждого режима свои и запоминаются при возврате к режиму.
- **Лимит 64 цвета.** Больше — ошибка (см. ниже).
- **Невалидный ввод и перелимит ведут себя одинаково:** палитра очищается, под строкой
  параметров показывается текст ошибки.
- **Гамут-кламп.** Любой цвет, не влезающий в sRGB, приводится уменьшением хромы
  (бинарный поиск по C при фиксированных L/H).

#### Режим 1 — `shade from x to y with z step`

Параметры: базовый цвет (пикер), `x`, `y`, `z`, `базовый shade` (default 500).

- Ряд оттенков: старт с `x`, далее кратные `z`, до `y` включительно.
  `50→800, z=100` → 50, 100, 200, …, 800. `z=50` → 50, 100, 150, …, 800.
- Обратный ввод (`x=800, y=50`) допустим; **список всегда сортируется по возрастанию номера**
  (направление ввода влияет только на границы диапазона).
- `базовый shade` **обязан лежать внутри `[min(x,y), max(x,y)]`**, иначе — ошибка.
- Светлота: 100 единиц shade = 10% пути к белому (вверх по светлоте) или к чёрному (вниз).
  Больший номер = темнее.

  ```
  p = (baseShade − N) / 1000          // >0 → светлее, <0 → темнее
  L' = L + p·(1 − L)                  // p > 0
  L' = L + p·L                        // p < 0  (p отрицательный → L уменьшается)
  ```

  Формула никогда не выходит за `[0, 1]`, шкала монотонна, дублей нет.
- Hue и chroma базы сохраняются, chroma клампится по гамуту.
- `alpha = 1`. `name = String(N)` («50», «100», …).

#### Режим 2 — `tonal scale`

Параметры: только базовый цвет.

- Фиксированный набор ступеней (11): 50, 100, 200, 300, 400, 500, 600, 700, 800, 900, 950.
- Целевые L зашиты константами (Tailwind-like):

  | 50 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 | 950 |
  |----|-----|-----|-----|-----|-----|-----|-----|-----|-----|-----|
  |0.97|0.94 |0.89 |0.81 |0.71 |0.62 |0.55 |0.47 |0.40 |0.33 |0.20 |

- **Анкор.** Ступень с ближайшим к базе целевым L получает **точный hex базового цвета**.
  Остальные строятся по таблице с hue базы.
- **Chroma — «колокол»**: пик в середине шкалы, спад к краям (светлые ступени бледные,
  тёмные — глубокие). Коэффициенты (подлежат визуальной калибровке на T3):

  | 50 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 | 950 |
  |----|-----|-----|-----|-----|-----|-----|-----|-----|-----|-----|
  |0.30|0.45 |0.65 |0.85 |0.97 |1.00 |0.98 |0.90 |0.78 |0.62 |0.45 |

  `C(N) = C_base × bell(N) / bell(anchor)` → гамут-кламп. Нормировка на `bell(anchor)`
  гарантирует, что анкор равен базе ровно.
- `name = String(N)`, `alpha = 1`.

#### Режим 3 — `interpolate A → B`

Параметры: цвет A (пикер + hex-инпут `#RRGGBBAA`), цвет B (так же), `N`, пространство.

- `N` = **общее число цветов, включая концы**. `N=5` → A, три промежуточных, B. Минимум `N=2`.
- Пространство выбирается в UI: **OKLab** (кратчайший путь, через серый центр) или
  **OKLCH** (hue по короткой дуге, промежутки остаются насыщенными). Default — OKLab.
- **Alpha интерполируется** линейно от `alpha(A)` к `alpha(B)`. Отсюда 8-значный hex-инпут.
- `name` = порядковый номер: «1», «2», …

#### Режим 4 — `alpha ramp`

Параметры: базовый цвет, `x`, `y`, `z` (в процентах).

- Ряд строится **тем же алгоритмом**, что и shade (старт с `x`, далее кратные `z`, до `y`),
  сортировка по возрастанию.
- `hex` у всех цветов одинаковый (базовый), меняется только `alpha = N / 100`.
- `name = String(N)` («10», «20», …).

#### Режим 5 — `harmony`

Параметры: базовый цвет, под-дропдаун схемы, угол (только для analogous и split-comp).

- Схемы и углы поворота hue от базы:

  | схема | углы |
  |-------|------|
  | complementary | 0, +180 |
  | analogous | −angle, 0, +angle (default angle = 30°) |
  | triadic | 0, +120, +240 |
  | split-complementary | 0, +180−angle, +180+angle (default angle = 30°) |
  | tetradic (square) | 0, +90, +180, +270 |

- **Светлота и хрома.** `base` — **точно выбранный hex**. Производные цвета получают L базы
  и **одинаковую хрому** — минимальную из максимально допустимых в sRGB для их hue
  (нормализация «в одну семью»). База в эту нормализацию не входит.
- Имена: `base`, `complement`, `analogous-1`, `analogous-2`, `triadic-1`, `triadic-2`,
  `split-1`, `split-2`, `tetradic-1`…`tetradic-3`.
- `alpha = 1`.

#### Режим 6 — `semantic set`

Параметры: базовый цвет, чекбокс «со шкалой».

- Роли: `primary`, `success`, `warning`, `danger`, `info`, `neutral`.
- `primary` = точный базовый hex.
- `success` / `warning` / `danger` / `info` — **фиксированные hue** в OKLCH
  (145° / 75° / 25° / 250°), L и C наследуются от базы, хрома клампится по гамуту.
  Семантика не ломается при любой базе (danger всегда красный).
- `neutral` — база с хромой ≈0.02 при её же L (серый с лёгким оттенком бренда).
- **Чекбокс «со шкалой»** (выкл. по умолчанию): каждая роль разворачивается в три ступени
  из tonal-алгоритма — `tonal[100]` / `tonal[500]` / `tonal[800]`, имена
  `role-light` / `role` / `role-dark`. Применяется ко всем ролям, включая primary и neutral.
- `name` = имя роли (поле `role` модели не трогаем).
- `alpha = 1`.

### Нефункциональные

- Строгая типизация, без `any` / `as` / `@ts-ignore`; файлы ≤ 200 строк.
- Пересчёт синхронный, в TS (без IPC-раунда в Rust) — иначе не будет живого превью.
- Rust-крейт `parser` и `src-tauri` не затрагиваются вовсе.
- Стили — CSS Modules + токены из `src/styles/tokens.css`, логические свойства.

## Архитектура

```
src/lib/color/
  oklch.ts          # sRGB ↔ OKLab ↔ OKLCH, гамут-кламп по хроме
src/lib/generate/
  types.ts          # GeneratorMode, GeneratorParams (дискриминированное объединение)
  steps.ts          # общий алгоритм ряда x→y→z (shade и alpha ramp)
  shade.ts
  tonal.ts          # таблицы L и bell, экспортируется и для semantic «со шкалой»
  interpolate.ts
  alpha-ramp.ts
  harmony.ts
  semantic.ts
  index.ts          # generate(params): Result<Omit<Color,'id'>[], string>
src/store/
  generator.ts      # состояние по paletteId (в памяти), общий базовый цвет
  project.ts        # + replaceColors(paletteId, colors) — одна undo-операция
src/components/
  PaletteGenerator.tsx / .module.css    # свитч, дропдаун, строка параметров, ошибка
  PaletteDetails.tsx                    # врезка панели в шапку
```

`generate()` — чистая функция: `(params) => { ok: colors } | { err: message }`.
Никакого доступа к стору, полностью юнит-тестируема.

## UI/UX

```
┌─ Настройка палитры ───────────────────────────────┐
│ [ Название палитры        ] [Дубликат] [+ Цвет]   │
│ [◉ Генерация]  [ shade from x to y ▾ ]            │  ← свитч + режим
│ [■] [x:50] [y:800] [z:100] [base:500]             │  ← строка параметров (по режиму)
│ ⚠ базовый shade должен быть внутри 50…800         │  ← ошибка (если есть)
├───────────────────────────────────────────────────┤
│ ■ #EFF6FF   50                                    │
│ ■ #DBEAFE   100                                   │
│ …                                                 │
└───────────────────────────────────────────────────┘
```

- Свитч исчезает, если палитра непустая и генератор выключен.
- Инвалидное поле подсвечивается, палитра при этом пуста.
- Пересчёт по `change` (не `input`) для числовых полей и пикера — чтобы протяжка
  ползунка цвета не забивала undo-стек.

## Edge cases

| Случай | Поведение |
|--------|-----------|
| `z = 0`, пустое поле, нечисловой ввод | палитра пуста + текст ошибки |
| `x = y` | палитра пуста + ошибка |
| `N < 2` в interpolate | палитра пуста + ошибка |
| Ряд > 64 цветов | палитра пуста + «слишком много цветов, максимум 64» |
| `baseShade` вне `[x, y]` | палитра пуста + ошибка |
| Обратный ввод `x > y` | валидно, список сортируется по возрастанию |
| `y` не кратен `z` (напр. `50→850, z=100`) | `y` включается как есть; последний интервал короче шага (`…, 800, 850`) |
| `x`/`y` вне домена (shade > 1000, alpha > 100) | палитра пуста + ошибка «границы не должны превышать N» |
| Небезопасное целое (> 2^53) в любом поле | палитра пуста + ошибка (иначе цикл шага не сходится) |
| Цвет вне sRGB после сдвига | хрома уменьшается до попадания в гамут |
| База — чистый серый (C=0) | harmony/semantic дадут серые (hue не определён) — допустимо |
| Пользователь удалил все цвета вручную | свитч снова доступен, параметры сброшены |

## Риски и митигации

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Колокол хромы выглядит «не как Tailwind» | средняя | коэффициенты вынесены в константу, калибруются на T3 по скриншоту |
| Живой пересчёт забивает undo-стек | средняя | пересчёт на `change`, не на `input`; лимит 64 цвета |
| Ошибка в sRGB↔OKLab матрицах даёт кривые цвета | низкая | unit-тест round-trip на опорных цветах (белый, чёрный, primaries) |
| Нормализация хромы в harmony удивляет («base ярче остальных») | средняя | так и решено осознанно; отражено в доке |
| Разрастание PaletteDetails.tsx > 200 строк | высокая | панель генератора — отдельный компонент |

## Тестовая стратегия

**T2 + T3 на каждой итерации.**

- **T2**: `pnpm typecheck`, `pnpm lint`, `pnpm test`.
  Unit (vitest):
  - `steps.ts`: ряд x→y→z в обе стороны, разные шаги, вырожденные вводы, лимит.
  - `oklch.ts`: round-trip sRGB→OKLCH→sRGB на опорных цветах; гамут-кламп.
  - каждый режим: снапшот набора цветов для эталонной базы.
  - валидация: каждый edge case из таблицы выше → ожидаемое сообщение об ошибке.
- **T3**: `pnpm tauri dev`, реальное окно, скриншот сгенерированной шкалы — глазами
  проверить равномерность и отсутствие «схлопывания» на краях.
- Ревью субагентом `code-reviewer` перед каждым коммитом.
